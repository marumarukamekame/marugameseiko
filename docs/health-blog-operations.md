# 健康ブログ運用ガイド

## 運用原則

健康ブログは **健康テーマを選択 → 記事を作成 → 記事内容に適した写真を選択・設定 → 下書き作成 → 内容確認 → 承認 → 公開** の順で運用します。AIが生成した健康・医療情報を自動公開しません。生成処理は常に `status: "draft"` で保存し、人による内容確認と承認後に限って公開します。

テーマは `content/blog/categories.json` の健康分野から選びます。自動生成時は直近2記事のカテゴリーを候補から外したうえでランダムに選ぶため、同じテーマの連続を避けられます。手動実行ではカテゴリーや具体的なテーマを指定できます。

## 写真の基準

- 各記事に、内容と一致する自然な**実写写真を1枚**用意します。SVG、イラスト、CGを通常のアイキャッチには使いません。
- 明るい自然光、清潔感、安心感、横浜らしい地域性、健康的で自然体の雰囲気を優先します。
- 白衣や病院が中心の医療広告風、高級サロン風、過度に演出された広告写真、派手な写真は避けます。
- 撮影・生成・素材サイトの別を問わず、公開前に利用権、人物の肖像・同意、場所、内容との整合性を確認します。
- 写真は `assets/images/blog/` に保存します。推奨形式は WebP、JPEG、PNG、AVIF、推奨比率は16:9です。
- 一覧ページと記事詳細上部には、記事JSONの同じ `image` と `imageAlt` を表示します。OGPと構造化データにも同じ写真を使います。

## 画像が未設定のとき

画像生成機能は現在の下書きスクリプトには接続していません。存在しない写真を生成済みとして扱わないため、新規下書きは次の状態で保存します。

- `image: null`
- `imageAlt: null`
- `imageStatus: "unassigned"`
- `imageFilename`: 保存予定のファイル名
- `imagePrompt`: 写真の選定・撮影・将来の画像生成連携に使う編集メモ

未設定の記事には、一覧と詳細の両方で「アイキャッチ写真 未設定」と明示されます。既存記事もSVGからこの移行状態へ変更しています。適切な写真を `assets/images/blog/<imageFilename>` に保存したら、`image`、具体的な `imageAlt` を設定し、`imageStatus` を `ready` に変更してください。ファイルがない状態や、実写でない画像のまま承認・公開してはいけません。

## 下書きから公開まで

1. 自動または手動で健康テーマを選び、記事JSONを `content/blog/posts/` に作ります。
2. 本文と `imagePrompt` をもとに実写写真を選定し、権利と内容を確認して `assets/images/blog/` に保存します。
3. `image`、`imageAlt`、`imageStatus: "ready"` を設定します。画像と本文を含む状態を下書きとして確定します。
4. 管理者が本文、断定表現、出典URLと記載内容、注意喚起、写真、代替テキスト、SEO項目、関連活動を確認します。必要に応じて有識者にも確認を依頼します。
5. 承認後にだけ `status` を `published` に変更し、`publishedAt` と `updatedAt` を `YYYY-MM-DD` で設定します。
6. `npm run blog:build` を実行し、生成されたHTMLと一覧データを同じPull Requestに含めます。公開前に一覧と詳細の写真が同じであることを目視確認します。

`npm run blog:validate` は、`ready` の画像がローカルのラスター形式で、代替テキストもあることを検証します。`unassigned` は移行中・下書きの状態を正直に示すためのもので、公開承認の条件を満たしません。

## 自動下書き

`.github/workflows/health-blog-drafts.yml` は月・水・金に下書きを作り、管理者確認用Pull Requestを作成します。手動実行ではカテゴリーとテーマを指定できます。Repository secret `OPENAI_API_KEY` と、必要に応じてRepository variable `OPENAI_MODEL` を設定してください。キーをHTML、JavaScript、記事JSON、ログへ記載しないでください。

API未設定時はワークフローが明示的に失敗し、架空の記事や画像URLは作りません。出典URLは許可済みの公的機関ドメインかつ到達確認できたものだけを下書きに残しますが、管理者による原文確認は必須です。

運用開始前に、レビュー担当者、CODEOWNERS、ブランチ保護、医療・健康情報の編集基準、専門家確認が必要な条件、写真の担当者と権利確認記録、公開後の定期見直し日を決めてください。
